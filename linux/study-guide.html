1. 리눅스(Linux)에 대한 오해와 진실 ★

커널운영체제
  • 흔한 오해: 리눅스는 하나로 통칭되는 운영체제(OS)이다.
  • 실제 정의: 리눅스는 운영체제의 핵심 소프트웨어인 커널(Kernel)을 의미한다.

운영체제(OS) vs 커널(Kernel)

구분뜻예 / 포함
운영체제 (OS)컴퓨터의 하드웨어 자원을 관리하고 사용자가 프로그램을 실행할 수 있도록 돕는 전체 소프트웨어Windows, macOS, Android, iOS 등
커널 (Kernel)운영체제 안의 핵심 소프트웨어장치 관리자, 네트워크 자원 관리, 보안, 시스템 소프트웨어 포함
포함 관계: 커널 ⊂ 운영체제. 노트 그림에서도 운영체제 상자 안에 커널 상자가 들어 있다.

2. 리눅스 커널의 5가지 핵심 특징 ★

오픈소스다중 사용자다중 작업
특징내용
오픈소스 (Open Source)누구나 소프트웨어를 사용, 수정, 배포할 수 있는 권한을 갖는다.
다중 사용자 (Multi-user)단일 사용자가 아닌 여러 사용자가 동시에 시스템에 접속해 효율적으로 운영할 수 있다.
다중 작업 (Multi-tasking)여러 작업을 미세한 시간 단위로 분할 실행해 마치 동시에 작업되는 것처럼 작동한다.
다양한 배포판 (Distributions)공통 리눅스 커널을 기반으로 다양한 응용 소프트웨어를 묶어 제공한다. 예: 데비안(Debian), 우분투(Ubuntu), 센트OS(CentOS), 레드햇 엔터프라이즈 에디션(RHEL)
활성화된 커뮤니티버그 리포팅, 문제 수정, 문서화에 수많은 개발자가 참여해 문제 해결 자원이 풍부하다.

3. 리눅스의 탄생 배경과 역사

UNIXGNUGNU/Linux

유닉스(UNIX)의 한계

  • 다중 사용자·다중 작업이 가능한 초기 모델이자 대부분 OS의 참조 모델이었다.
  • 그러나 상용 소프트웨어로서 소수가 독점해 활용에 한계가 있었다.

GNU 프로젝트 (1983년)

  • 리차드 스톨만(Richard Stallman)이 자유소프트웨어재단(FSF)을 설립하고, 소프트웨어의 자유로운 사용·복제·수정·배포를 지향하는 자유 소프트웨어 운동을 시작했다.
  • GNU의 의미: "GNU's Not Unix". 유닉스와 호환되면서 자유롭게 쓸 수 있는 프로그램을 만들고자 했다.
  • 주요 포함 프로그램: 문서 편집기 Emacs, C 컴파일러 모음 GCC 등.

리눅스 커널과의 결합 (1991년)

  • 대학생이었던 리누스 토르발스(Linus Torvalds)가 초기 리눅스 커널을 개발·배포했다.
  • 이 커널이 GNU 프로젝트와 결합해 오늘날의 리눅스 운영체제(GNU/Linux)로 완성되었다.
  • 엄밀히 '리눅스'는 커널을 가리키지만, 보통 GNU/Linux 또는 리눅스 배포판 전체를 통칭한다.

2. 셸(Shell)의 개념과 역할 ★

명령어 해석기
셸: 사용자와 커널 사이에서 소통을 돕는 명령어 해석기(Command Interpreter) 소프트웨어
  • 작동 방식: 사용자가 셸에 간접적으로 명령을 내리면, 셸이 이를 해석해 커널에 전달하고 커널의 처리 결과를 다시 사용자에게 전달한다.
  • 사전적 의미: '껍데기'. 하드웨어를 제어하는 핵심(커널)을 감싸고 사용자가 커널을 제어하도록 돕는다. 노트 그림도 하드웨어 → 커널 → 셸을 조개껍데기처럼 겹쳐 그렸다.

3. 패키지(Package)와 의존성(Dependency) 문제

패키지의존성
패키지: 특정 소프트웨어, 라이브러리, 설정 파일 등을 하나로 묶어 관리하는 배포 단위
  • 윈도우의 설치 프로그램과 비슷하지만, 리눅스에서는 하나의 소프트웨어가 여러 개의 독립된 패키지로 구성되는 경우가 많다.
  • 의존성 문제: 소프트웨어 하나를 작동시키려면 여러 패키지가 함께 설치되어야 하는 연관 관계. 연관 패키지가 업데이트되면 기존 패키지가 정상 동작하지 않는 충돌이 생길 수 있다.
  • 과거 리눅스에서는 사용자가 모든 의존성 문제를 직접 해결해야 했다.

1. 가상화(Virtualization)의 개념과 장점 ★

가상화VM
가상화: 물리적인 하드웨어를 추상화해 소프트웨어로 구현하는 기술. 큰 방 하나를 작은 방 여러 개로 나누어 쓰는 것과 비슷하다.
  • 가상 머신 (VM, Virtual Machine): 가상화 기술로 만든 가상 컴퓨터. 안에 게스트 운영체제와 응용 프로그램이 올라간다.
  • 장점: 물리 하드웨어 자원을 효율적으로 쓰고, 컴퓨터 한 대에서 여러 운영체제를 동시에 실행할 수 있다.

2. 하이퍼바이저(Hypervisor)의 개념과 종류 ★

Type 1Type 2VirtualBox
하이퍼바이저: 가상화를 구현하기 위해 하드웨어 자원을 추상화하고 유연하게 분할·관리하는 전용 프로그램
베어메탈 (Type 1)호스트 기반 (Type 2)
쌓는 순서하드웨어 → 하이퍼바이저 → VM하드웨어 → 호스트 OS → 하이퍼바이저 → VM(게스트 OS)
장점호스트 OS 없이 하드웨어를 직접 제어. 여러 VM 관리 시 성능과 보안 우수기존 OS를 삭제하지 않아 편리. 실습 교육용으로 적합
단점한 단계를 더 거쳐 통신해 성능이 다소 떨어지고 보안 관리 지점이 늘어남

버추얼박스 (VirtualBox): 오라클(Oracle)의 오픈소스 가상화 소프트웨어(Type 2). 다양한 호스트·게스트 OS를 지원하고 라이선스 제약 없이 실습할 수 있다. 기타 하이퍼바이저: VMware, Xen, MS Hyper-V 등.

3. 맥(macOS) 환경 버추얼박스 설치 방법

  • CPU 확인: 애플 메뉴 > '이 맥에 관하여'에서 프로세서/칩 확인.
  • 2020년 이후의 애플 실리콘(M1, M2 등)과 인텔용 설치 파일이 나뉘어 있으므로 사양에 맞는 .pkg를 받는다.
  • 설치 절차: .pkg 더블 클릭 → 설치 위치 확인 후 설치(Install) → 관리자 권한 인증(비밀번호 또는 지문) → 설치 파일 삭제 여부 선택 후 실행.

4. 윈도우(Windows) 환경 버추얼박스 설치 방법

사전 필수 패키지 (오류 발생 시)

  • 설치가 중단되는 팝업이 뜨면 'Microsoft Visual C++ 재배포 가능 패키지'를 먼저 설치한다.
  • Win + i > 시스템 > 정보에서 시스템 종류(예: X64 기반 프로세서)를 확인해 맞는 파일을 받는다.
  • 설치 후 반드시 재부팅한 뒤 버추얼박스를 설치한다.

설치 절차

2. 루트(/) 하위의 주요 기본 디렉토리 역할 ★

디렉토리역할

1. 파일 및 디렉터리 복사 명령어 (cp) ★

cp-r-i
cp (Copy): 파일이나 디렉터리를 다른 위치로 복사하거나 다른 이름으로 복사본을 만든다.

  • 기본 동작: -i 없이 실행하면 같은 이름이 있어도 묻지 않고 덮어쓴다.

1. 명령어 실행 결과를 변수에 저장하는 방법 ★

$( )명령어 치환

명령어 치환 $(명령어): 명령어의 실행 결과를 변수에 담거나 바로 출력한다. 기본 형식은 변수명=$(명령어).

#!/bin/bash

DATE=$(date +%Y-%m-%d)
echo "Today is $DATE"
# Today is 2026-10-01

⚠️ 노트 정정: 노트 설명은 "연도와 월만 추출"로 되어 있지만, %Y-%m-%d는 연-월-일을 모두 뽑는다. 실행 결과도 2026-10-01이다.

2. 위치 매개변수(Positional Parameters)의 개념과 종류 ★

$0$1$#$@
위치 매개변수: 스크립트 실행 시 뒤에 전달하는 인자(Argument)의 순서에 따라 자동으로 값이 할당되는 특별한 변수
변수설명
$0실행된 스크립트의 이름(또는 경로)
$1첫 번째 인자
$2 ~ $9두 번째 ~ 아홉 번째 인자
${10} ~열 번째 인자부터. 두 자리 이상은 중괄호 필요
$#전달된 인자의 개수
$@전달된 모든 인자 (개별적으로 처리)
$*전달된 모든 인자 (하나의 문자열로 처리)

💡 해설: $@와 $*의 차이는 큰따옴표로 감쌌을 때("$@", "$*") 드러난다. 아래 실습에서 두 줄 출력이 같은 이유도 그냥 나열해 출력했기 때문이다.

3. 위치 매개변수 실습 예시 (args.sh)

#!/bin/bash

echo "Script name: $0"
echo "First argument: $1"
echo "Second argument: $2"
echo "Arguments number: $#"
echo "All arguments: $@"
echo "All arguments: $*"

apple banana cherry를 인자로 실행한 결과 (노트 이미지):

Script name: /home/yulian/bin/args.sh
First argument: apple
Second argument: banana
Arguments number: 3
All arguments: apple banana cherry
All arguments: apple banana cherry

주의: 인자를 전달하지 않으면 변수에 아무 값도 저장되지 않으므로 필요한 인자를 함께 입력한다.

4. 위치 매개변수 응용: 디렉터리 사용량 조회 스크립트 (usage.sh) ★

du/dev/null
  • du (Disk usage): 파일이나 디렉토리가 하드디스크 공간을 얼마나 차지하는지 확인. du [옵션] [경로]
  • -s (Summary): 디렉터리 내부 전체 용량을 요약.
  • -h (Human-readable): K, M, G 등 읽기 쉬운 단위로 표시.
  • 2> /dev/null: 권한 없는 디렉터리에서 나는 Permission denied 에러를 화면에 출력하지 않고 버린다.
#!/bin/bash

du -sh $1 2> /dev/null

실행 예: ./usage.sh /etc. 첫 번째 인자로 받은 /etc의 사용량만 오류 메시지 없이 요약해 출력한다.

⚠️ 노트 정정: 노트의 du -sh /etc $1 >2 /dev/null은 두 군데가 다르다. /etc가 고정으로 들어가 항상 함께 출력되고, >2는 "2"라는 파일로 출력을 보낸다. 에러 리다이렉션은 2>이다.

3. 형식 지정 출력 명령어 (printf) ★

printf "name: %s, score: %d" yulian 85
#      └─ 문자열 형식 ──────┘ └ 출력값 ┘
# %s ← yulian,  %d ← 85
# 결과: name: yulian, score: 85

💡 해설: printf는 echo와 달리 자동 줄 바꿈이 없어서, 줄을 바꾸려면 형식 끝에 \n을 쓴다.

1. 수식 연산 명령어 및 표현식 (expr, let, 이중 소괄호) ★

exprlet(( ))

반복문의 조건식과 증감 연산을 위해 수식을 계산하는 3가지 방법이다.

expr

가장 기본적인 산술 연산 명령어. 명령어, 연산자, 피연산자 사이에 반드시 공백을 둔다.

expr 4 + 2
expr 10 - 3
expr 10 '*' 2
expr 10 '/' 5

expr 1 = 1   #1    비교: 참이면 1
expr 1 != 1  #0    거짓이면 0

x=5

echo $sum   #15

let

expr과 달리 변수명 앞의 $를 생략할 수 있고 공백 없이 쓴다. 단항 연산자(x++, x+=1)를 지원한다.

y=5
let sum=x+y

let x++

⚠️ 노트 정정: 노트의 let x +=1처럼 let 안에 공백을 넣으면 오류가 난다. let x+=1 또는 let "x += 1"로 쓴다.

현대 셸 스크립트에서 가장 많이 쓰는, 가장 개선된 방식이다. $나 공백에 구애받지 않고 C언어 스타일의 수식과 단항 연산자를 쓴다.

x=2
y=10
r=$((x*y))
echo $r   #20
# -------------------
((x++))
echo $x  #3

3. while 및 until 반복문 (조건식 기반 반복) ★

whileuntil

반복 횟수가 불확실하거나 특정 조건을 만족할 때까지 반복할 때 쓴다.

실행종료
while조건이 참(True)인 동안거짓(False)이 되는 순간
until조건이 거짓(False)인 동안참(True)이 되는 순간

while 예시

#!/bin/bash

num=1
while ((num <= 5))
do
	echo "Number: $num"
	((num++))
done

until 예시

#!/bin/bash

num=1
until ((num > 5))
do
	echo "Number: $num"
	((num++))
done

⚠️ 노트 정정: 노트의 두 예시는 echo "Number: $sum"으로 적혀 있다. $sum은 선언되지 않아 빈 값이 나오므로 $num이어야 한다.

2. 주요 조건별 검색 옵션 (-name, -type, -size, -perm 등) ★

-name-type-size-perm

이름으로 검색: -name

지정한 파일명과 일치하는 대상을 검색하며, 와일드카드(*, ?)와 조합할 수 있다.

💡 해설: 패턴을 따옴표로 감싸야 셸이 먼저 펼치지 않고 find에 그대로 전달한다(24강).

파일 타입으로 검색: -type

옵션대상
-type f일반 파일(File)
-type d디렉터리(Directory)
-type l심볼릭 링크(Link) 파일
-type b / -type c블록 장치 / 문자 장치 파일

파일 크기로 검색: -size

  • 크기 기준에 +(초과), -(미만)를 붙여 특정 범위의 파일만 추출한다.
  • 단위: k (KiB), M (MiB), G (GiB), c (Byte).

⚠️ 노트 정정: 노트는 이 예시를 "5MiB 초과 10MiB 미만"으로 설명한다. 실제로 find는 크기를 지정 단위로 올림해 비교하므로 -size -10M은 9MiB 이하만 고른다. 실행해 보면 9.3MiB 파일은 10M으로 올림되어 빠진다. 경계까지 정확히 다루려면 -size -10485760c처럼 바이트로 쓴다.

권한으로 검색: -perm

8진수 허가권 수치와 정확히 일치하는 대상을 검색한다(27강).

find ~ -perm 770

기타 유용한 검색 옵션

  • -user [계정명]: 특정 사용자 계정이 소유한 파일 검색.
  • -empty: 용량이 0바이트이거나 내부가 비어 있는 파일·디렉터리 검색.

3. 검색 결과 일괄 명령어 실행 (-exec) ★

-exec{}\;

검색된 파일이나 디렉터리를 대상으로 지정한 명령어(ls, cp, mv, rm 등)를 한 번에 일괄 적용한다.

find [경로] [조건] -exec [실행할명령어] {} \;
요소역할
{}찾아낸 개별 파일·디렉터리의 경로가 이 위치로 하나씩 자동 치환됨
\;-exec 뒤 명령어와 옵션의 끝을 구분. 반드시 맨 뒤에 포함
find /usr/bin -size +5M -exec ls -lh {} \;      # 5MiB 초과 파일의 상세 정보 일괄 출력
find /usr/bin -size +5M -exec cp {} ~/test/ \;  # 5MiB 초과 파일을 ~/test/로 한 번에 복사

💡 해설: ; 앞의 역슬래시는 셸이 ;를 명령 구분자로 먼저 해석하지 않게 막는다. 복사 대상 ~/test/는 미리 만들어 둔다. -exec rm을 쓰기 전에는 -exec 없이 실행해 대상을 먼저 확인한다.

3. 서브넷 마스크 (Subnet Mask)의 개념과 동작 ★

서브넷 마스크AND 연산
서브넷 마스크: IP 주소에서 어디까지가 네트워크 주소이고 어디까지가 호스트 주소인지 구분하기 위해, 호스트 영역을 가리고 네트워크 영역만 나타내는 값
  • 동작 원리: 2진수로 표현한 IP 주소와 서브넷 마스크를 AND 연산해 네트워크 주소를 추출한다.
  • 예시: 서브넷 마스크가 255.0.0.0이면 1이 8개인 형태이므로, AND 연산으로 네트워크 주소(예: 10.0.0.0)만 추출되고 나머지는 호스트 용도로 구분된다.

4. CIDR (사이더) 표기법 및 리눅스 IP 조회 명령어 ★

CIDRip addr
CIDR (Classless Inter-Domain Routing, 사이더): 서브넷 마스크를 길게 적지 않고, IP 주소 뒤에 슬래시(/)와 서브넷 마스크 안의 1의 개수를 표시해 네트워크 비트를 나타내는 방식

예: 10.0.2.15/24에서 /24는 네트워크 주소에 24비트를 쓴다는 뜻이며, 서브넷 마스크 255.255.255.0과 같다.

리눅스 IP 주소 확인 명령어

ip addr

외부 연결 네트워크 카드의 IP 주소와 CIDR 방식 표기(inet 10.0.2.15/24), MAC 주소 등을 확인할 수 있다.

💡 해설: 10.0.2.15는 첫 숫자만 보면 A 클래스인데 /24를 쓴다. CIDR의 이름이 "Classless"인 이유로, 클래스에 묶이지 않고 네트워크 비트 수를 정할 수 있다. MAC 주소는 ip addr 출력의 link/ether 줄에 나온다.

1. 방화벽(Firewall)의 개념과 트래픽 방향 ★

인바운드아웃바운드화이트리스트
방화벽: 외부 네트워크와 내부 네트워크 사이에 위치해 지정된 보안 정책에 따라 트래픽을 허용(Allow)하거나 차단(Deny/Reject)하는 보안 시스템
방향뜻
인바운드(Inbound)외부 네트워크 → 내부 네트워크로 들어오는 트래픽
아웃바운드(Outbound)내부 네트워크 → 외부 네트워크로 나가는 트래픽

화이트리스트 기반 보안 정책: 들어오는 트래픽을 기본적으로 모두 차단(Deny)하고, 사용할 서비스나 포트만 선택적으로 허용(Allow)하는 엄격한 관리를 권장한다.

2. 우분투 계열 방화벽 관리 (ufw) ★

ufw

ufw (Uncomplicated Firewall): 직관적이고 단순한 명령 형식을 가진 우분투의 기본 방화벽 관리 도구.

기본 제어 및 상태 확인

명령동작
sudo ufw status verbose활성화 상태와 수립된 규칙 상세 조회
sudo ufw enable방화벽 활성화
sudo ufw disable방화벽 비활성화
sudo ufw reload규칙 재적용
sudo ufw reset모든 규칙 초기화 및 비활성화
sudo ufw default deny incoming기본 인바운드 차단 정책 설정

규칙 설정

명령동작
sudo ufw allow 80/tcp80번 TCP 포트 허용
sudo ufw deny 22/tcp22번 TCP 포트 차단
sudo ufw reject 22/tcp패킷 거부 메시지를 응답하며 차단
sudo ufw allow ssh, sudo ufw allow http서비스명으로 허용
sudo ufw allow from 192.168.1.10특정 IP의 접근 허용
sudo ufw allow from 10.0.0.0/24 to any port 22CIDR IP 대역(31강) 및 특정 포트 지정
sudo ufw delete allow 80/tcp등록된 허용 규칙 삭제

💡 해설: 원격(SSH)으로 접속한 서버에서는 sudo ufw allow ssh를 먼저 하고 enable한다. 순서가 바뀌면 자신의 접속까지 막힐 수 있다.

3. 레드햇/로키 계열 방화벽 관리 (firewall-cmd) ★

firewall-cmdZone--permanent

firewall-cmd: 레드햇(RHEL), 로키 리눅스 계열에서 방화벽 데몬(firewalld)을 제어하는 명령어 도구.

존(Zone) 기반 관리: 네트워크 인터페이스별로 구역(public, home, internal, trusted 등)을 분리해 세밀한 규칙을 적용한다. 기본 존은 public.

명령동작
sudo firewall-cmd --state동작 상태 확인 (running 여부)
sudo firewall-cmd --list-all현재 구역의 서비스 및 포트 규칙 전체 출력
sudo firewall-cmd --add-service=httphttp 서비스 일시 허용
sudo firewall-cmd --remove-service=httphttp 서비스 차단
sudo firewall-cmd --add-port=80/tcp80번 TCP 포트 허용

영구 적용: --permanent

재부팅 후에도 설정이 유지되도록 적용한다.

주의: --permanent로 추가한 규칙은 반드시 sudo firewall-cmd --reload를 입력해야 시스템에 최종 반영된다.
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload

1. LAMP 스택과 워드프레스의 개념 ★

WordPressCMSLAMP
워드프레스 (WordPress): 전 세계에서 가장 많이 쓰는 오픈소스 CMS(Content Management System) 도구. 복잡한 코딩 없이 블로그, 기업 홈페이지, 쇼핑몰, 커뮤니티 사이트 등을 구축하는 웹 애플리케이션

LAMP 스택: 동적 웹 애플리케이션이 실행되는 데 필요한 4가지 핵심 환경 요소의 앞 글자를 딴 명칭.

PPHP동적 웹페이지를 생성하는 서버 스크립트 언어php

2. LAMP 스택 구성 요소 설치 과정 ★

sudo apt install apache2                             # 아파치 웹 서버 설치
sudo apt install php libapache2-mod-php php-mysql    # PHP 및 아파치/MySQL 연동 모듈 설치
sudo apt install mysql-server                        # MySQL 데이터베이스 서버 설치
sudo systemctl start mysql                           # 데이터베이스 서비스 실행
sudo systemctl restart apache2                       # 새 PHP 모듈과 설정을 반영하도록 웹 서버 재시작

3. 워드프레스 다운로드 및 파일 배치 ★

wgettarwww-data
wget https://wordpress.org/latest.tar.gz       # 최신 워드프레스 압축 파일 다운로드
tar -xzvf latest.tar.gz                        # .tar.gz를 한 번에 해제해 wordpress 디렉터리 생성
sudo cp -r wordpress/* /var/www/html/          # 웹 서버의 기본 문서 루트로 전체 복사
sudo chown -R www-data:www-data /var/www/html  # 웹 서버 전용 계정에 소유권을 재귀적으로 부여
sudo chmod -R 755 /var/www/html                # 소유자 7, 그룹·기타 5를 재귀적으로 부여

⚠️ 노트 정정: 전달받은 노트에서 wget 주소가 [suspicious link removed]로 지워져 있어, 다음 줄의 latest.tar.gz에 맞는 워드프레스 공식 주소로 복원했다.

💡 해설: tar의 z는 gzip 처리 옵션이다(22강). 또 Apache를 설치하면 /var/www/html/index.html 기본 페이지가 있고 이 파일이 index.php보다 먼저 열린다. 워드프레스 대신 Apache 안내 화면이 나오면 sudo rm /var/www/html/index.html로 지운다.

4. MySQL 데이터베이스 및 연동 계정 생성 ★

CREATEGRANT
sudo mysql -u root -p      # MySQL 관리자 접속
CREATE DATABASE wordpress;                                    -- 1. 데이터베이스 생성
CREATE USER 'admin'@'localhost' IDENTIFIED BY '1234';         -- 2. 사용자 생성 및 비밀번호 설정
GRANT ALL PRIVILEGES ON wordpress.* TO 'admin'@'localhost';   -- 3. 권한 부여
FLUSH PRIVILEGES;                                             -- 4. 권한 반영
EXIT;                                                         --    종료

💡 해설: 1234는 실습용 값이다. 외부에 공개되는 서버에서는 추측하기 어려운 비밀번호를 쓴다.

5. 웹 브라우저를 통한 워드프레스 웹 설치 마법사 진행 ★

  1. 웹 브라우저 접속: 주소창에 http://[서버 IP 주소]/ 또는 http://localhost/ 입력.
  2. 언어 선택: 한국어 또는 영어.
  3. DB 연동 정보 입력: DB 이름(wordpress), 계정명(admin), 비밀번호(1234), DB 호스트(localhost).
  4. 사이트 기본 정보 및 관리자 생성: 사이트 제목, 로그인용 계정명과 안전한 비밀번호, 이메일 주소를 작성하고 Install WordPress 클릭.
  5. 완료 및 대시보드 진입: 관리자 계정으로 로그인해 대시보드(Dashboard)에서 글 작성, 테마/스타일 변경 등 웹사이트를 관리한다.

💡 해설: VM 밖의 브라우저로 접속하려면 32강의 Bridged나 포트 포워딩이 필요하고, 방화벽을 켰다면 33강의 sudo ufw allow http도 필요하다. 서버 IP는 31강의 ip addr로 확인한다.
