LECTURE 01

리눅스 개념과 특징, 활용 사례

리눅스에 대한 오해와 진실
SYNOPSIS
  • 리눅스는 엄밀히 말하면 운영체제가 아니라 커널이다. (커널 ⊂ 운영체제)
  • 핵심 특징: 오픈소스, 다중 사용자, 다중 작업, 다양한 배포판, 활발한 커뮤니티
  • GNU 프로젝트(1983) + 리누스 토르발스의 커널(1991) = GNU/Linux

운영체제 vs 커널

  • 운영체제(OS): 하드웨어 자원을 관리하고 프로그램 실행을 돕는 전체 소프트웨어. 예: Windows, macOS, Android, iOS
  • 커널(Kernel): OS의 핵심. 장치 관리, 네트워크 자원 관리, 보안, 시스템 소프트웨어를 담당
운영체제 (OS)응용 프로그램 · 셸 · 유틸리티
커널 = 리눅스장치 · 네트워크 · 보안
하드웨어CPU · 메모리 · 디스크

커널의 5가지 핵심 특징

특징설명
오픈소스누구나 사용, 수정, 배포할 수 있다.
다중 사용자여러 사용자가 동시에 접속해 시스템을 쓸 수 있다.
다중 작업작업을 아주 짧은 시간 단위로 나눠 실행해 동시에 도는 것처럼 동작한다.
다양한 배포판같은 커널 위에 서로 다른 소프트웨어를 묶어 제공한다. 예: Debian, Ubuntu, CentOS, RHEL
활발한 커뮤니티버그 리포트, 수정, 문서화에 많은 개발자가 참여한다.

탄생 배경

UNIX
상용 · 소수 독점→ GNU 프로젝트 (1983)
리차드 스톨만 · FSF+ 리눅스 커널 (1991)
리누스 토르발스= GNU/Linux
  • UNIX: 다중 사용자·다중 작업의 원조이자 대부분 OS의 참조 모델. 상용이라 활용에 한계가 있었다.
  • GNU: "GNU's Not Unix". 유닉스와 호환되는 자유 소프트웨어를 만드는 운동. Emacs, GCC 등이 포함된다.
  • 보통 "리눅스"라고 하면 GNU/Linux 또는 배포판 전체를 통칭한다.

주요 활용 분야

분야리눅스를 쓰는 이유
서버 · 클라우드높은 안정성, 네트워크 보안, 무료 라이선스. AWS, GCP, Azure의 기반
슈퍼컴퓨터자유로운 커스텀과 정밀한 하드웨어 제어. 대부분이 리눅스 기반
개발자 데스크톱다양한 개발 도구와 유연한 제어 환경
모바일 (Android)가볍고 모듈화가 쉬우며 하드웨어에 맞게 수정 가능
임베디드 · IoT스마트 TV, 내비게이션, 카메라 등. 제한된 자원에 맞춘 최적화
SELF CHECK
"리눅스"는 정확히 무엇을 가리키나요?

운영체제의 핵심 소프트웨어인 커널입니다. 일상적으로는 GNU/Linux 또는 배포판 전체를 부르는 말로도 씁니다.

안드로이드가 리눅스 커널을 쓰는 이유는?

가볍고 모듈화가 쉬우며 다양한 하드웨어에 맞게 수정할 수 있기 때문입니다.

LECTURE 02

리눅스 시스템 구성요소와 셸

Linux Shell 기초
SYNOPSIS
  • 구성: 응용 프로그램 → 셸 → 커널 → 하드웨어
  • 셸 = 사용자의 명령을 해석해 커널에 전달하는 명령어 해석기
  • 대부분의 리눅스 기본 셸은 bash. 설치된 셸 목록은 cat /etc/shells

시스템 구성요소

응용 프로그램문서 작성 · 웹 · 게임
셸 (Shell)명령 해석 · 전달
커널 (Kernel)프로세스 · 파일 · 장치 드라이버
하드웨어CPU · GPU · 메모리 · 키보드
  • 응용 프로그램: 사용자가 원하는 특정 작업을 하는 소프트웨어
  • 셸: 사용자와 커널 사이의 인터페이스
  • 커널: 장치, 프로세스, 네트워크, 보안, 파일 관리. 장치 드라이버가 내장되어 있다
  • 하드웨어: 장치 드라이버를 통해 신호가 식별되고 제어된다 (예: 키보드 입력 이벤트 처리)

셸의 역할

사용자명령 →셸 (해석)→커널 (처리)→ 결과 →셸→사용자

셸(shell)은 "껍데기"라는 뜻으로, 하드웨어를 제어하는 핵심(커널)을 감싸고 사용자가 커널을 다룰 수 있게 돕습니다.

셸의 종류

셸명령특징
본 셸 (Bourne)sh최초 유닉스의 기본 셸
C 셸cshC 언어 스타일 문법
콘 셸 (Korn)ksh본 셸 + 명령어 완성 등 기능 추가
배시 셸 (Bourne-Again)bash대부분 리눅스의 기본 로그인 셸
기타tcsh, zsh필요에 따라 선택해 사용

bash vs sh 실습 비교

$ cat /etc/shells   # 설치된 셸 목록
$ sh                # 본 셸로 전환
$ exit              # 다시 bash로 복귀
bashsh
ls 색상파일/디렉토리를 색으로 구분색 구분 없음
Tab 자동 완성지원미지원 (공백 입력됨, 전체 이름을 직접 입력)
SELF CHECK
키보드 입력이 커널에 전달될 때 중간에서 신호를 변환하는 것은?

커널에 내장된 장치 드라이버(Device Driver)입니다.

현재 시스템에 설치된 셸 목록을 보는 명령은?

LECTURE 03

리눅스 배포판과 패키지 관리 기초

Linux Distro & Package
SYNOPSIS
  • 배포판 = 리눅스 커널 + 셸 + 응용 소프트웨어를 묶은 완성된 OS
  • 데비안 계열과 레드햇 계열 두 가지만 알아도 대부분 다룰 수 있다
  • 패키지 관리자가 의존성을 자동으로 해결한다: apt (데비안), dnf/yum (레드햇)

배포판이란

  • 모든 배포판은 리눅스 커널을 공통으로 쓰고, 어떤 셸과 응용 프로그램을 탑재하느냐에 따라 달라진다.
  • 목적에 따라 수백 가지가 있고 지금도 계속 생겨난다.

대표 배포판과 패키지 관리자

배포판특징패키지 관리자
Slackware가장 오래된 배포판 중 하나. 단순성, 수동 설정 위주라 전문가용pkgtool
Debian 계열
Debian, Ubuntu		자유 소프트웨어 철학, 높은 안정성·호환성. 서버, 데스크톱, 임베디드apt
Red Hat 계열
RHEL, Rocky Linux		기업용 상용. 강력한 기술 지원, 기업 서버·클라우드dnf / yum
Android리눅스 커널 기반 모바일 OS. 스마트폰, TV, IoTAPK · Play 스토어

패키지와 의존성

  • 패키지: 소프트웨어, 라이브러리, 설정 파일 등을 하나로 묶은 배포 단위. 리눅스에서는 한 소프트웨어가 여러 패키지로 나뉘는 경우가 많다.
  • 의존성 문제: 한 소프트웨어가 동작하려면 여러 패키지가 함께 필요하다. 연관 패키지가 업데이트되면 충돌이 생길 수 있다.
  • 과거에는 사용자가 직접 해결해야 했지만, 지금은 패키지 관리자가 설치·업데이트·삭제와 의존성 해결을 한 줄로 처리한다.
$ sudo apt install tree   # Ubuntu / Debian
$ sudo dnf install tree   # Rocky / RHEL
SELF CHECK
모든 배포판의 공통점과 차이점은?

공통점은 리눅스 커널을 쓴다는 것, 차이점은 탑재한 셸과 응용 프로그램입니다.

Rocky Linux에서 패키지를 설치할 때 쓰는 관리자는?

dnf (또는 yum). 레드햇 계열이기 때문입니다.

LECTURE 04

가상화 개념과 VirtualBox 설치

VirtualBox Installation
SYNOPSIS
  • 가상화 = 물리 하드웨어를 추상화해 소프트웨어로 구현. 만들어진 가상 컴퓨터가 VM
  • 하이퍼바이저 Type 1(베어메탈) vs Type 2(호스트 기반). VirtualBox는 Type 2
  • Windows에서 설치가 막히면 Visual C++ 재배포 패키지부터 설치 후 재부팅

가상화와 VM

  • 큰 방 하나를 여러 작은 방으로 나눠 쓰는 것과 비슷하다.
  • 장점: 하드웨어 자원을 효율적으로 쓰고, 한 컴퓨터에서 여러 OS를 동시에 실행할 수 있다.

하이퍼바이저 종류

Type 1 · 베어메탈
VMGuest OS
하이퍼바이저
하드웨어
호스트 OS 없이 하드웨어를 직접 제어. 성능·보안 우수
Type 2 · 호스트 기반
VMGuest OS
하이퍼바이저VirtualBox
Host OSWindows · macOS
하드웨어
기존 OS를 그대로 쓰니 편리, 실습용으로 적합. 한 단계를 더 거쳐 성능은 다소 낮고 보안 관리 지점이 늘어남

VirtualBox: Oracle이 만든 오픈소스 Type 2 하이퍼바이저. 다양한 호스트/게스트 OS를 지원하고 라이선스 제약 없이 실습할 수 있다. 다른 예: VMware, Xen, Hyper-V

설치 방법

macOS
  • Apple 메뉴 › 이 Mac에 관하여에서 칩 확인
  • Apple 실리콘(M1, M2…)과 Intel용 .pkg가 다르니 맞는 것을 받는다
  • .pkg 실행 → 설치 → 관리자 인증 → 완료
Windows
  • 설치 중단 팝업이 뜨면 Microsoft Visual C++ 재배포 패키지 먼저 설치
  • Win+I › 시스템 › 정보에서 아키텍처(x64 등) 확인 후 맞는 파일 설치
  • 설치 후 반드시 재부팅, 그다음 VirtualBox 설치
  • 네트워크 일시 끊김 경고 → 예. Python Core/Win32 옵션은 VM 자동화가 필요할 때만
SELF CHECK
실습용으로 Type 2 하이퍼바이저가 적합한 이유는?

기존 호스트 OS를 지우지 않고 그 위에 설치해 쓸 수 있기 때문입니다.

Type 2가 Type 1보다 불리한 점은?

호스트 OS를 한 단계 더 거쳐 통신하므로 성능이 다소 떨어지고 보안 관리 지점이 늘어납니다.

LECTURE 05

우분투 리눅스 설치

Ubuntu on VirtualBox
SYNOPSIS
  • 우분투 = 데비안 계열 대표 배포판. GUI, 기본 소프트웨어, 풍부한 커뮤니티
  • VM 이름은 영문+숫자만 (공백·한글 금지)
  • RAM은 호스트의 절반 이하, CPU는 코어 수의 절반 이하로 할당

우분투 배포판 4가지 유형

유형인터페이스용도
DesktopGUI개인용 컴퓨터, 개발 작업
ServerCLI웹·DB·파일 서버. 자원 소모가 적고 성능 최적화
Cloud—클라우드 환경. 가상화, 컨테이너, 자동화 도구 통합
Core—저사양 IoT, 임베디드용 경량판

ISO 파일 이름 읽기

ubuntu-24.04-desktop-amd64.iso

ubuntu.com에서 데스크톱 ISO를 받는다. 자동 다운로드가 안 되면 "Download now" 링크로 회원가입 없이 받을 수 있다.

VirtualBox 설정 단계

단계내용

무인 설치계정/암호를 미리 넣어 자동 설치. 국가·언어·네트워크를 직접 정하려면 "건너뛰기"
게스트 확장공유 폴더, 클립보드 공유, 해상도 자동 조절. 함께 설치 권장
메모리호스트 16GB면 4–8GB

SELF CHECK
가상 디스크를 25GB로 설정하면 실제 디스크 25GB가 바로 사라지나요?

아닙니다. VM이 저장할 수 있는 최대 용량 한도이고, 실제로는 쓴 만큼만 차지합니다.

VM 이름으로 "내 우분투"가 안 되는 이유는?

공백과 한글이 오류를 일으킬 수 있습니다. 영문과 숫자 조합으로 지어야 합니다.

LECTURE 06

로키 리눅스 설치

Rocky Linux on VirtualBox
SYNOPSIS
  • Rocky Linux = RHEL 호환 커뮤니티 배포판. CentOS의 빈자리를 대체
  • 입문자는 DVD ISO 추천. 무인 설치를 건너뛰고 수동 설정
  • 게스트 → 호스트 제어권 반환: Windows는 오른쪽 Ctrl, macOS는 Command

등장 배경

  • CentOS는 레드햇 계열의 대표 커뮤니티 배포판이었다.
  • 레드햇에 합류한 뒤 정책이 바뀌어, 안정화 배포판이 아니라 RHEL보다 앞서 가는 테스트 성격(CentOS Stream)이 되었다.
  • 기존 CentOS의 철학을 잇기 위해 Rocky Linux가 등장했다.
보충CentOS가 레드햇에 합류한 것은 2014년이고, CentOS Stream 중심으로 전환한다고 발표한 것은 2020년입니다.

ISO 3가지 유형

ISO크기특징
DVD가장 큼인터넷 없이 데스크톱과 소프트웨어를 한 번에 설치. 입문자 추천
Boot중간부팅 후 인터넷으로 필요한 패키지만 골라 설치
Minimal가장 작음명령어 기반 패키지만. 서버·경량 환경

파일명 구조: 배포판 - 버전 - 아키텍처 - 설치 유형 .iso

VM 설정

  • 무인 설치 건너뛰기 체크 → VM이 꺼진 상태로 생성되므로 "시작"을 직접 누른다.
  • RAM과 CPU는 호스트 자원의 50% 미만 (16GB → 8GB 미만, 8코어 → 4개 미만).
  • 가상 디스크 기본 20GB, 이미지 파일 확장자는 .vdi.

키보드/마우스 제어권

  • VM 화면을 클릭하면 제어권이 게스트 OS로 넘어간다.
  • 호스트로 되돌리는 호스트 키: Windows는 오른쪽 Ctrl, macOS는 Command.
  • 오른쪽 Ctrl이 없는 키보드라면 VirtualBox 환경설정 › 입력에서 호스트 키를 다른 키로 바꿀 수 있다.

설치 요약 화면 (붉은 항목은 필수)

  • 설치 목적지: 로컬 디스크 선택 후 완료
  • root 계정: 기본 비활성. 교육·복구 목적으로 활성화하고 비밀번호 설정
  • 사용자 생성: 영문 계정, 관리자 권한 체크, 비밀번호 설정
  • 경고가 사라지면 "설치 시작" → 완료 후 "시스템 재시작" → 로그인 → 터미널 실행

LECTURE 09

절대 경로와 상대 경로

Absolute vs Relative Path
SYNOPSIS
  • 절대 경로: /부터 전체 주소. 어디서 출발해도 같다
  • 상대 경로: 현재 위치 기준 길 안내. 출발지에 따라 달라진다
  • 기호: / 루트·구분자, . 현재, .. 상위, ~ 홈

경로 기호

기호의미예시
/맨 앞이면 루트, 중간이면 구분자/home/ubuntu
.현재 디렉토리./hello.sh
..상위(부모) 디렉토리../file
~로그인한 사용자의 홈~/file

같은 이동, 두 가지 표현

# 준비: 홈에서 A/B/C 만들기
$ cd ~
$ mkdir -p A/B/C
$ tree A

# 홈 → B 로 이동
$ cd /home/ubuntu/A/B   # 절대 경로
$ cd A/B                # 상대 경로 (현재 위치가 홈일 때)

# B → /home 으로 이동
$ cd /home              # 절대 경로
$ cd ../../..           # 상대 경로 (B → A → ubuntu → home)
정정노트에는 B에서 /home으로 갈 때 cd ../..라고 적혀 있었는데, /home/ubuntu/A/B에서 ../..는 /home/ubuntu입니다. /home까지 가려면 ../../..가 필요합니다.
  • 목적지가 루트에 가까우면 절대 경로, 현재 위치 근처라면 상대 경로가 편하다.
  • tree가 없으면 sudo apt install tree (Ubuntu) 또는 sudo dnf install tree (Rocky)로 설치한다.
SELF CHECK
/home/ubuntu에서 첫 번째 /와 두 번째 /의 의미는?

첫 번째는 루트 디렉토리, 두 번째는 디렉토리 구분자입니다.

LECTURE 10

파일 복사와 이동 (cp, mv)

Copy & Move
SYNOPSIS
  • cp [옵션] 원본 대상 — 디렉토리 복사엔 -r 필수, 덮어쓰기 확인은 -i
  • mv 원본 대상 — 이동과 이름 변경을 모두 담당. 디렉토리도 옵션 없이 이동
  • 옵션 없는 cp/mv는 같은 이름 파일을 묻지 않고 덮어쓴다

cp

$ cp A/B/C/test1 A/test2    # 다른 이름으로 복사
$ cp A/B/C/test1 B/         # 디렉토리로 복사 (이름 유지)
$ cp -r C B/D               # 디렉토리 C를 B 안에 D라는 이름으로 복사
$ cp -i test1 A/            # 같은 이름이 있으면 y/n 확인

mv

$ mv A/B/C/test A/B/C/test1   # 같은 위치에서 이름만 변경
$ mv A/B/C A/                 # 디렉토리 C를 A 바로 아래로 이동 (-r 불필요)
cpmv
원본남는다사라진다 (옮겨짐)
디렉토리 대상-r 필요옵션 불필요
이름 변경복사본 이름 지정대상 이름만 바꾸면 rename

실습 팁

  • ↑ 키로 이전 명령어를 불러와 다시 실행하거나 고칠 수 있다.
  • 목적지 뒤에 /를 붙이면(A/) 디렉토리임을 분명히 할 수 있다.
SELF CHECK
파일 이름을 바꾸는 명령은?

mv 기존이름 새이름. 리눅스에는 별도의 rename 기본 명령 대신 mv를 씁니다.

C가 디렉토리인데 -r 옵션이 없어서입니다. cp -r C D로 실행합니다.

SYNOPSIS

표준 입출력

0과 1은 기본값이라 보통 생략하고, 2는 표준 출력과 구분하기 위해 반드시 적는다.

기호동작예시

<파일 내용을 입력으로wc -l < ls.txt
2> / 2>>에러만 파일로mkdir 2> error.txt
&> / &>>출력과 에러를 한 파일로ls /etc /nope &> all.txt
2> /dev/null에러 메시지 버리기du -sh /* 2> /dev/null

$ history | sort | less               # 명령 이력을 정렬해 페이지로 보기
$ cat /etc/passwd | grep ubuntu       # ubuntu가 들어간 줄만

ls
목록 출력|grep .txt
.txt 줄만 남김|wc -l
줄 수 = 개수
  • |는 키보드의 \(또는 ₩) 키 위에 있다.
  • grep 문자열: 해당 문자열이 들어간 줄만 걸러낸다.
  • wc: 줄·단어·바이트 수를 센다. -l 줄, -w 단어, -c 바이트.

LECTURE 16

셸 변수와 환경 변수

Shell vs Environment Variables
SYNOPSIS
  • 선언 name=value (등호 앞뒤 공백 금지), 참조 $name
  • 셸 변수는 현재 셸에서만, 환경 변수(export)는 하위 프로세스까지 유효
  • 조회 set / printenv·env, 삭제 unset, 영구 저장은 ~/.bashrc

셸 변수 규칙

$ name=ubuntu        # OK
$ name = ubuntu      # 오류: name 이라는 명령을 찾게 됨
$ echo name          # → name (그냥 문자열)
$ echo $name         # → ubuntu (변수 값)
  • 영문 대소문자, 숫자, _만 사용. 첫 글자는 숫자가 될 수 없다.
  • 대소문자를 구분한다: user와 USER는 다른 변수.

확인과 삭제

$ set | grep USER    # 셸 변수 중 USER만 찾기
$ unset score        # 변수 자체를 삭제 ($ 붙이지 않음)
  • 셸 변수는 셸(터미널)을 닫으면 사라진다.
  • 계속 쓰려면 ~/.bashrc(zsh는 ~/.zshrc)에 선언을 적어 둔다.

LECTURE 17

셸 스크립트 기본 동작 원리

Shebang · chmod · PATH
SYNOPSIS
  • 구성: 셰뱅 #!/bin/bash + 주석 # + 명령어 본문
  • 실행: 경로 지정(./hello.sh) + 실행 권한(chmod +x)
  • 어디서나 실행: ~/bin을 PATH에 추가, ~/.bashrc에 적어 영구화

스크립트 구조

#!/bin/bash          # 셰뱅: 이 파일을 bash로 해석하라
# 인사를 출력하는 스크립트   # 주석
echo "Hello Linux"   # 본문: 위에서부터 순서대로 실행

반복 작업 자동화, 실행 순서 보장, 시스템 관리·백업·로그 수집에 쓴다. 확장자 .sh는 구분용이며 필수는 아니다.

실행할 때 나는 오류 두 가지

$ hello.sh
hello.sh: command not found       # → 경로가 없다: ./hello.sh 로 실행
$ ./hello.sh
bash: ./hello.sh: Permission denied   # → 실행 권한(x)이 없다
$ chmod +x hello.sh                 # 실행 권한 부여 (ls에서 초록색으로 보임)
$ ./hello.sh
Hello Linux

어디서나 실행되게 하기

$ mkdir ~/bin
$ mv hello.sh ~/bin
$ export PATH=$PATH:~/bin     # 임시: 터미널을 닫으면 사라짐
$ hello.sh                    # 어느 위치에서든 실행

# 영구 적용
$ vi ~/.bashrc                # 맨 끝에 export PATH=$PATH:~/bin 추가
$ source ~/.bashrc            # 지금 셸에 바로 적용

ls, pwd를 경로 없이 실행할 수 있는 것도 그 실행 파일 위치가 PATH에 들어 있기 때문이다.

SELF CHECK
"Permission denied"가 나오면?

실행 권한이 없는 것입니다. chmod +x 파일명으로 권한을 줍니다.

.bashrc를 고친 뒤 바로 적용하려면?

source ~/.bashrc

LECTURE 18

셸 스크립트 위치 매개변수

$0 · $1 · $# · $@
SYNOPSIS
  • 명령어 치환: 변수=$(명령어)
  • $0 스크립트 이름, $1–$9 인자, ${10} 이상은 중괄호
  • $# 인자 개수, $@·$* 모든 인자

명령어 치환

#!/bin/bash
DATE=$(date +%Y-%m-%d)     # date 결과(연-월-일)를 변수에 저장
echo "Today is $DATE"
# Today is 2026-10-01

위치 매개변수

$ ./args.sh  apple  banana  cherry
#   $0        $1     $2      $3      $# = 3
변수의미
$0실행한 스크립트 이름(경로)
$1 ~ $9첫 번째 ~ 아홉 번째 인자
${10} …열 번째 이상은 중괄호로 감싼다
$#전달된 인자 개수
$@모든 인자 (반복문에서 개별 요소로 처리)
$*모든 인자 ("$*"는 하나의 문자열로 처리)

args.sh

#!/bin/bash
echo "Script name: $0"
echo "First argument: $1"
echo "Second argument: $2"
echo "Arguments number: $#"
echo "All arguments: $@"
echo "All arguments: $*"

인자 없이 실행하면 $1, $2는 빈 값이 된다.

응용: 디렉토리 사용량 조회 (usage.sh)

#!/bin/bash
du -sh "$1" 2> /dev/null    # 첫 번째 인자 경로의 용량만, 오류는 버림
$ ./usage.sh /etc
6.5M	/etc
  • du(disk usage): 파일·디렉토리가 차지하는 디스크 공간. -s 합계만, -h K·M·G 단위.
  • 2> /dev/null: Permission denied 같은 에러를 화면에 출력하지 않고 버린다.
정정노트의 du -sh /etc $1 >2 /dev/null은 두 군데가 틀렸습니다. /etc가 고정으로 들어가 있어 항상 /etc도 함께 출력되고, >2는 "2"라는 파일로 출력을 보내는 뜻이 됩니다. 에러 리다이렉션은 2>입니다.
SELF CHECK
./run.sh a b c d에서 $#과 $3은?

$#은 4, $3은 c입니다.

열두 번째 인자는 어떻게 쓰나요?

${12}. $12라고 쓰면 $1 뒤에 문자 2가 붙은 것으로 해석됩니다.

LECTURE 19

셸 스크립트 사용자 입력과 출력

echo · read · printf
SYNOPSIS
  • echo -n "안내: "; read VAR — 같은 줄에서 입력 받기
  • 변수명 없이 read하면 값은 $REPLY에 저장
  • printf로 서식 지정 출력: %s %d %f %.2f %x %o

입력 받기

#!/bin/bash
echo -n "Enter your name: "; read NAME   # -n: 줄바꿈 없이 출력
echo "Hello, $NAME"

read                                      # 변수명 생략
echo "You typed: $REPLY"
  • echo는 출력 후 자동으로 줄을 바꾼다. 안내문 옆에서 입력을 받으려면 -n.
  • 패키지 삭제 시 "계속하시겠습니까? (Y/N)" 같은 확인 과정이 이 방식이다.
더 알아두기bash에서는 read -p "Enter your name: " NAME로 안내문과 입력을 한 번에 처리할 수도 있습니다.

printf 서식 지정자

지정자출력예시 → 결과
%s문자열printf "%s\n" Linux → Linux
%d10진 정수printf "%d\n" 42 → 42
%f실수 (기본 소수점 6자리)printf "%f\n" 3.14 → 3.140000
%.2f소수점 자리수 지정printf "%.2f\n" 3.14159 → 3.14
%x / %X16진수 (소/대문자)printf "%X\n" 255 → FF
%o8진수printf "%o\n" 8 → 10
$ printf "Name: %s, Age: %d\n" "$NAME" 23
Name: ubuntu, Age: 23

echo와 달리 printf는 줄바꿈을 자동으로 넣지 않으므로 \n을 직접 쓴다.

SELF CHECK
read 뒤에 변수명을 안 쓰면 입력값은 어디로?

$REPLY에 저장됩니다.

2.5를 "2.50"으로 출력하려면?

printf "%.2f\n" 2.5

LECTURE 20

셸 스크립트 조건문

test · if · else · case
SYNOPSIS
  • test 조건 = [ 조건 ] — 대괄호 안쪽 양옆에 공백 필수
  • if 조건; then … else … fi
  • case "$var" in 패턴) … ;; *) … ;; esac

test와 if

#!/bin/bash
if test -e file.txt; then
    echo "The file exists"
else
    echo "The file does not exist"
fi

test는 조건을 평가해 참/거짓을 돌려준다. 보통 단독이 아니라 if와 함께 쓴다.

자주 쓰는 test 조건식

파일참일 때
-e 파일존재한다
-f 파일일반 파일이다
-d 파일디렉토리다
-r / -w / -x읽기 / 쓰기 / 실행 가능
-s 파일크기가 0보다 크다
문자열 · 숫자참일 때
"$a" = "$b"문자열이 같다
"$a" != "$b"다르다
-z "$a" / -n "$a"빈 문자열 / 비어 있지 않음
-eq -ne숫자 같음 / 다름
-lt -le -gt -ge< ≤ > ≥

대괄호 형태

#!/bin/bash
str="Hello World"
if [ "$str" = "Hello World" ]; then
    echo "same"
fi
정정노트의 str = "Hello"와 if[ ... ]는 둘 다 오류가 납니다. 변수 선언은 = 앞뒤에 공백이 없어야 하고(str="Hello"), if와 [ 사이, [ 안쪽 양옆에는 공백이 있어야 합니다. [도 하나의 명령어이기 때문입니다.
  • 문자열 비교 시 변수는 "$str"처럼 큰따옴표로 감싼다. 값에 공백이 있거나 비어 있어도 오류가 나지 않는다.

case

#!/bin/bash
echo "1) Shutdown the system"
echo "2) Restart the system"
echo -n "What do you want? (1/2): "
read answer

case "$answer" in
    1) echo "Shutdown the system" ;;
    2) echo "Restart the system" ;;
    *) echo "Wrong command" ;;    # 어느 패턴에도 맞지 않을 때
esac

각 패턴은 ;;로 끝나고, 전체는 esac(case를 거꾸로)로 닫는다. if가 fi로 닫히는 것과 같은 규칙이다.

SELF CHECK
if ["$a" = "b"]가 실패하는 이유는?

[와 ] 안쪽에 공백이 없어서 셸이 ["$a"를 하나의 명령으로 읽습니다. [ "$a" = "b" ]로 씁니다.

숫자 $n이 10보다 큰지 검사하는 조건식은?

[ "$n" -gt 10 ] 또는 (( n > 10 ))

LECTURE 21

셸 스크립트 반복문

expr · let · (( )) · for · while · until
SYNOPSIS
  • 산술: expr(공백 필수) < let < $(( )) (가장 많이 씀)
  • for: 리스트·범위·C 스타일 / while: 참인 동안 / until: 거짓인 동안
  • 모두 do … done으로 감싼다

산술 연산 3가지

exprlet$(( )) / (( ))
공백필수없어야 함자유
$ 표기필요생략 가능생략 가능
x++, x+=1불가가능가능
곱셈'*'로 감싸야 함**
# expr: 연산자 양옆 공백 필수, 비교는 참 1 / 거짓 0
expr 4 + 2          # 6
expr 10 '*' 2       # 20
expr 1 = 1          # 1
x=5; sum=$(expr $x + 10); echo $sum   # 15

# let: $ 생략, 공백 없이
x=3; y=5
let sum=x+y; echo $sum   # 8
let x++;     echo $x     # 4
let x+=1;    echo $x     # 5

# 이중 소괄호: C 스타일
x=2; y=10
r=$((x * y)); echo $r    # 20
((x++));      echo $x    # 3
정정노트의 let x +=1처럼 let 안에 공백이 들어가면 오류가 납니다. let x+=1 또는 let "x += 1"로 씁니다.

for

# 리스트
for name in Kim Lee Park
do
    echo "Hello, $name!!"
done

# 범위 {시작..끝}
for i in {1..10}
do
    echo "Count: $i"
done

# C 스타일: 1, 3, 5, 7, 9
for ((i=1; i<10; i+=2))
do
    echo "Step: $i"
done

범위 연산자는 명령어에도 쓸 수 있다: touch test{1..10}은 test1–test10을 한 번에 만든다.

while vs until

num=1
while ((num <= 5))
do
    echo "Number: $num"
    ((num++))
done
num=1
until ((num > 5))
do
    echo "Number: $num"
    ((num++))
done
조건이 참조건이 거짓
while반복 실행종료
until종료반복 실행

두 예시는 결과가 같다 (1–5 출력). 조건만 반대로 쓴 것이다.

정정노트의 while/until 예시에서 echo "Number: $sum"은 $num이어야 합니다. $sum은 선언되지 않아 빈 값이 출력됩니다.
SELF CHECK
expr 3*4가 계산되지 않는 이유는?

공백이 없어서 하나의 문자열로 취급되고, *는 셸이 와일드카드로 해석합니다. expr 3 '*' 4로 씁니다.

반복 횟수를 미리 알 수 없을 때 쓰는 반복문은?

while 또는 until입니다.

LECTURE 22

파일 묶기와 압축

tar · gzip · bzip2 · xz · zip · file
SYNOPSIS
  • 묶기(tar)와 압축(gzip/bzip2/xz)은 다른 작업. 보통 묶은 뒤 압축한다
  • tar -cf 묶기, -tf 목록, -xvf 풀기
  • zip은 묶기+압축을 한 번에, 윈도우와 호환

tar로 묶기

passwdhoststar →test.tar
묶음 (크기 그대로)gzip →test.tar.gz
압축
옵션뜻

xeXtract: 풀기
tList: 풀지 않고 목록만
vVerbose: 진행 과정 출력
fFile: 아카이브 파일명 지정 (옵션 맨 뒤, 바로 뒤에 파일명)
$ tar -cf test.tar passwd hosts   # 묶기
$ tar -tf test.tar                # 목록 확인
$ tar -xvf test.tar               # 풀기

$ tar -cf test.tar ./*      # 모든 파일을 묶어 test.tar
$ gzip test.tar             # → test.tar.gz (test.tar는 사라짐)
$ gzip -d test.tar.gz       # 다시 test.tar
$ bzip2 -k test.tar         # 원본 유지하며 test.tar.bz2
더 알아두기tar에 압축 옵션을 함께 주면 한 번에 처리됩니다. tar -czvf a.tar.gz dir/로 묶고 압축, tar -xzvf a.tar.gz로 풉니다. bzip2는 j, xz는 J.

zip / unzip

$ zip test.zip test1 test2   # 묶기 + 압축 한 번에
$ zip -r dir.zip dir/        # 디렉토리는 -r
$ unzip test.zip             # 같은 파일이 있으면 [y]es/[n]o/[A]ll/[N]one/[r]ename 선택

file: 진짜 파일 유형 확인

$ mv test.tar.gz test.zip
$ file test.zip
test.zip: gzip compressed data, ...   # 확장자와 무관하게 실제 내용으로 판단

tar만 했을 때 용량이 줄어드나요?

아닙니다. tar는 여러 파일을 하나로 묶을 뿐이고, 용량을 줄이는 건 gzip, bzip2, xz 같은 압축 프로그램입니다.
